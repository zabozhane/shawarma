# Шаурма

Сайт для ларька с шаурмой. Клиент с телефона выбирает блюда, получает номер заказа и забирает его у окошка. Продавец и владелец ведут заказы и меню в админке.

- **Сайт клиента** (`/`): меню, корзина с лимитом, вход по коду из письма, выбор времени, номер заказа, личный кабинет, 9 языков (русский, английский, китайский, корейский, азербайджанский, узбекский, таджикский, турецкий, казахский). Язык выбирается по настройкам телефона.
- **Админка** (`/admin`): очередь заказов со звуком и пуш-уведомлениями, меню и цены, стоп-лист, клиенты и блокировки, настройки кухни, отчёты, сотрудники.

## Запуск на своём компьютере

Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
git clone https://github.com/zabozhane/shawarma.git
cd shawarma
docker compose up --build
```

Когда в консоли появится «Шаурма работает», откройте:

| Что | Адрес |
|---|---|
| Сайт клиента | http://localhost:3000 |
| Админка | http://localhost:3000/admin (логин `owner`, пароль `shawarma`) |
| Письма с кодами входа | http://localhost:8025 |

Локально письма никуда не уходят: их перехватывает Mailpit, и код для входа видно на странице http://localhost:8025.

Остановить: `Ctrl+C` или `docker compose down`. Данные базы сохраняются между запусками. Начать с чистой базы: `docker compose down -v`.

## Как работает защита от незабранных заказов

- В одном заказе не больше 2 штук из каждого раздела меню: 2 шаурмы, 2 закуски, 2 напитка, 2 соуса (число настраивается). Нагрузку на кухню считают только шаурма и закуски.
- У клиента может быть только один активный заказ.
- Готовить начинают к выбранному времени, а не в момент заказа. Пока готовка не началась, клиент может отменить заказ.
- Через 30 минут после готовности продавец может отметить «Не забрали». После этого заказы с той же почты и с того же телефона продавец подтверждает вручную. Третий незабранный заказ за 60 дней блокирует почту на 30 дней.
- Одноразовые почтовые ящики не принимаются.

## Как считается время готовности

Время делится на окна по 10 минут. Владелец указывает, сколько шаурм кухня успевает за окно (по умолчанию 2) и сколько из них в час пик отдаётся онлайн-заказам (по умолчанию 1, второе место остаётся живой очереди). Каждый заказ занимает ближайшие свободные места, поэтому клиент сразу видит честное время. Продавец может сдвинуть время кнопкой «+10 мин» или поставить приём на паузу.

## Разработка без Docker

Нужны Node.js 20+ и PostgreSQL 16.

```bash
npm install
cp .env.example .env          # поправьте DATABASE_URL под свою базу
npm run dev                    # сервер на :3000 и фронтенд с горячей перезагрузкой на :5173
npm test                       # тесты расчёта загрузки и правил защиты
```

Переменные окружения описаны в [.env.example](.env.example). Без `SMTP_HOST` письма печатаются в консоль сервера.

## Запуск на сервере

1. Сервер с Docker, домен и HTTPS (например, через Caddy или nginx). Без HTTPS не работают пуш-уведомления и установка сайта на экран телефона.
2. В `.env` задайте `PUBLIC_URL=https://ваш-домен`, длинный `SESSION_SECRET`, `COOKIE_SECURE=true`, свой `ADMIN_PASSWORD` и настройки почтового сервиса (`SMTP_*`).
3. `docker compose up -d --build`.

Почты клиентов — персональные данные. Для клиентов из России сервер и база должны находиться в России, а на сайте нужна политика обработки персональных данных.

## Устройство

```
server/          Express + PostgreSQL
  slots.js       расчёт загрузки кухни (чистые функции, покрыты тестами)
  rules.js       правила защиты (лимит, ручное подтверждение, блокировка)
  orders.js      заказы и смена статусов
  auth.js        вход клиента по коду из письма и вход сотрудников
  notify.js      письма, пуш-уведомления, живые обновления
  messages.js    тексты писем и пушей на 9 языках
web/src/client   сайт клиента (React)
web/src/admin    админка (React)
web/public/sw.js сервис-воркер для пуш-уведомлений
```
